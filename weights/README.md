# Model Artifacts

This directory contains the trained model artifacts required for real inference.

**No model binaries are committed to this repository.**  
This file documents what is required and where to obtain it.

## Required Artifacts

| Artifact | Model Type | Loader | Expected Framework / Format | Role |
|----------|------------|--------|----------------------------|------|
| `weights/yolo_solar.pt` | YOLOv8 object detector | `ultralytics.YOLO` | PyTorch / Ultralytics checkpoint | Detect solar panel regions in uploaded images |
| `weights/mobilenet_solar.pth` | MobileNetV2 classifier | `torchvision.models.mobilenet_v2` + `torch.load` | PyTorch state dict (`state_dict`) | Classify detected panels into fault classes |
| `weights/xgboost_solar.joblib` | XGBoost regression pipeline | `joblib.load` | scikit-learn-compatible pipeline (joblib) | Predict efficiency loss from engineered features |

## How the Application Uses These Files

1. **YOLO detector** (`weights/yolo_solar.pt`)  
   Loaded by `models/model_manager.py::ModelManager._load_detector()` via `ultralytics.YOLO(str(path))`.  
   Must be a valid YOLOv8 weights file compatible with the `ultralytics` package installed in `requirements.txt`.

2. **MobileNet classifier** (`weights/mobilenet_solar.pth`)  
   Loaded by `models/model_manager.py::ModelManager._load_classifier()` via `torch.load(path, weights_only=True)`.  
   Must be a PyTorch `state_dict` for a `torchvision.models.mobilenet_v2` model whose final classifier layer outputs `num_classes=6` (matching `configs/settings.yaml → models.mobilenet.num_classes`).

3. **XGBoost predictor** (`weights/xgboost_solar.joblib`)  
   Loaded by `models/model_manager.py::ModelManager._load_predictor()` via `joblib.load(path)`.  
   Must be a serialized scikit-learn-compatible pipeline object with a `.predict(features)` method that accepts the feature DataFrame constructed by `services/feature_engineering.py`.

## Why These Files Are Not in Git

Model artifacts are large binary files that are:
- Generated by a separate training process not included in this repository
- Potentially proprietary or institution-specific
- Better managed as external artifacts or via Git LFS if needed

They are intentionally excluded by `.gitignore`:
```
weights/*.pt
weights/*.pth
weights/*.joblib
weights/*.pkl
```

## Obtaining the Artifacts

These artifacts must be obtained from the **legitimate project owner / training process**.

There is currently no public download URL, release asset, or training script in this repository that can reproduce these files.

### What to Do If You Are a Developer

1. Contact the project owner to obtain the trained artifacts.
2. Place the files in this directory (`weights/`).
3. Verify with:
   ```bash
   py -3.12 scripts/check_model_artifacts.py
   ```
4. Run the application:
   ```bash
   py -3.12 -m streamlit run app.py
   ```

### What to Do If You Are a Researcher / Reviewer

- You may inspect the architecture, configuration, tests, and pipeline logic without the artifacts.
- The application will start successfully, but any attempt to run real inference will produce a clear `ModelLoadError` explaining which artifact is missing and how to configure a custom path.

## Custom Paths

If you store artifacts in a non-default location, update `configs/settings.yaml`:

```yaml
models:
  yolo:
    weights: "path/to/your/yolo_solar.pt"
  mobilenet:
    weights: "path/to/your/mobilenet_solar.pth"
  xgboost:
    weights: "path/to/your/xgboost_solar.joblib"
```

Paths are resolved relative to the project root by `models/model_manager.py`.

## Important Warnings

- **Do not substitute generic pretrained models.** The pipeline expects models fine-tuned on the solar panel fault dataset with the specific class labels and feature distributions defined in `configs/settings.yaml`.
- **Do not fabricate or generate fake model files** merely to make the application appear functional. Fake weights will produce meaningless or misleading predictions.
- **Do not commit binary artifacts** to this repository unless the repository's contribution policy explicitly changes.
